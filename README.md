# Zel for Scoop

The Scoop bucket maintained by **Shebka** for the Zellij website engine's `zel`
CLI. Shebka uses the GitHub account `mylife-inc`. This is not the unrelated
Zellij terminal multiplexer.

## Install

Install [Scoop](https://scoop.sh/) first, then run in PowerShell:

```powershell
scoop bucket add mylife-inc https://github.com/mylife-inc/scoop-bucket
scoop install mylife-inc/zel
zel --version
```

The current package is **0.2.0-rc.18**, a development preview, for native Windows
x64 and ARM64. The manifest uses immutable release URLs and SHA-256 checksums.
Portable Markdown builds run entirely inside the CLI. Rich builds download and
cache a private renderer; no separate Docker, Node.js, npm or Python installation
is needed. Both outputs open by double-clicking `site/index.html`. Cached rich
builds accept `--offline`. Rich `--target static` builds share the cache for HTTP hosting. Image builds,
hosted Next `dev` and optional PDF generation retain their documented container prerequisites.


Rich `zel check`, `zel watch` and `zel view --watch` also use the cached renderer
without separately installed tools. The first rich operation downloads it;
`--offline` reuses the verified cache for both `file` and `static` targets.
Static deployment builds and optional import validation also use that cache. Validation reports source errors without executing authored
MDX; live preview retains the last successful site after an invalid edit.

The nine bundled starters include `book-classic`, `book-technical` and
`book-study`. With `pdf.enabled: true`, both static and Next book images include
a matching downloadable PDF; the toolchain stays outside the serving image.
Print supports English/French/German/Spanish LTR and Arabic RTL, pinned
Amiri/Libertinus fonts and `pdf.style` customization. `zel create my-api -t api-platform`
uses the light/dark Kie theme.

The hosted section composer now includes video, layered layouts, semantic
content, product selectors, scroll stories and reuse of eight built-in sections.
Run `zel presets` to list nine editable section presets, or create one with
`zel ns -p product-overview --out content/sections/overview.yaml`.
Rich builds use the automatically downloaded matching renderer.

Scoop keeps the executable and shim in its managed directories. Zellij downloads use `ZELLIJ_HOME`, defaulting to `%USERPROFILE%\Dev\config\zellij`: renderers live under `cache\engines`, and remote templates under `cache\templates`. Set an absolute `ZELLIJ_HOME` to change the resource root. Standalone installers use its `bin` directory; Scoop retains its own installation paths. Existing caches are not silently moved.

## Update or remove

```powershell
scoop update
scoop update zel
scoop uninstall zel
```

Scoop owns this installation. `zel upgrade`, including `--force`, refuses to
replace its binary and prints `scoop update zel` before any network request.
Use the Scoop commands above for updates.
The package does not edit your PowerShell profile or install a completion script
into it. See [CLI completions](https://github.com/mylife-inc/Zellij/blob/main/examples/zellij-docs/content/02-cli/completions.mdx) for
optional shell setup.

For commands that use a container, the matching engine is
`ghcr.io/mylife-inc/zellij-base:0.2.0-rc.18` (already the CLI default).
[Release assets](https://github.com/mylife-inc/releases/releases/tag/zellij-v0.2.0-rc.18)
and [source/issue tracker](https://github.com/mylife-inc/Zellij).

## Maintenance

`bucket/zel.json` is generated by Zellij's `scripts/scoop-manifest.mjs` from a
verified release checksum inventory. Adopt new candidates only after native
package acceptance; update the manifest, this version reference and the CI
version together. The workflow pins the tested Zellij acceptance tooling and
Scoop v0.6.0. It checks both CPU architectures under Windows PowerShell 5.1 and
PowerShell 7, including a bad-checksum update, a fixture package-revision update,
portable builds, ownership protection, public installation and uninstall.
The fixture revision is only a test and does not claim a new CLI release.

Maintainers may dispatch acceptance with `upgrade_from` set to a still-published
previous version before retirement. This additionally
installs that real CLI from its checksummed HTTPS archive and upgrades it to the
current release through an isolated Git bucket. Leaving the input empty avoids
depending on retired downloads.

The rc.16 release also includes verified WinGet manifests and ownership
protection. The rc.15 Microsoft catalog submission awaits moderator approval;
Scoop is the currently available managed Windows installation channel.
